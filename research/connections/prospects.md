# What is worth connecting next

The [measured findings](findings.md) narrow the original [cross-field questions](questions.md). Keep the native producers and their existing caches as controls; replace internals when the complete operation benefits.

1. **Join current discovery with a genuine diagnostic consumer.** Reuse the retained native parser and observed namespace keys, then measure navigation plus current diagnostics through real edits and dependency changes. Validate source locations, negative lookups, cycles and invalidation against the authoritative tool. Continue only if the extra shared boundary saves more work than it produces.
2. **Give retained results an explicit evidence and lifetime contract.** Connect source/configuration generations, diagnostics and test observations without promoting historical evidence to current validation. The compiler's diagnostic-cache and history failures provide concrete cases. Include late results, changed configuration, interrupted execution and bounded retention.
3. **Test the user-facing discovery benefit.** The Jinja replay establishes selection equivalence and export overhead. A useful next comparison must include unfamiliar repositories, varied queries and independently selected tasks, with reasoning/task-completion costs measured. Preserve literal search and native language/test services as controls.
4. **Measure structural reuse before another representation or executor.** Unchanged local file structure can survive namespace rebinding; a compact extra graph or forked runtime may still lose overall. Charge extraction, rebinding, initialization, restoration, dirty/private memory and cleanup. Compare native database reuse and competently reset warm workers before claiming an isolation speedup.
