# What is worth testing next

The next experiments should connect the demonstrated pieces and broaden their workloads. The [broader sharing pass](workflows/coverage.md) now includes compiler, data, test, repository and schema controls. More isolated format tuning is useful only when a profile identifies meaningful work in the complete operation.

## Use shared models across different workloads

The [theory track](theory/README.md) now has a [bounded implementation round](science/README.md), covering sets, patches, incremental facts, scheduling, retention, feedback, nature-inspired policies, geometry, actual GPU work and compiler-pass overlap. Its [coverage map](science/coverage.md) distinguishes actual execution from simulations. The [ranked follow-ups](science/prospects.md) prioritize incremental observations, maintained set summaries and dependency-aware retention. Use sparse CPU algorithms, fixed batching and ordinary clustering as strong controls; these often beat the more elaborate alternatives. Public protocol and production-service decisions remain open.

## Connect workspace authority to a larger build graph

The [single-frontend follow-up](compiler/followthrough/findings.md) now retains current IR and continues directly on a miss. Next combine that boundary with inexpensive exact-input lookup and sound dependency observations in the real graph. Preserve ccache controls, diagnostics, side products and the packing/target/assembly/debug regressions; AST fingerprints are not object-cache proofs.

The new 33-TU Ninja project connects source generations, generated inputs and configuration changes, but its scheduler uses fixed baseline dependencies. The [three-TU Clang observation extension](science/graphs/README.md) now exercises dynamic refresh and negative lookups; integrate that boundary into the larger graph before making general invalidation claims. Extend beyond one worker and preserve independent artifacts and matched parallel Ninja controls. Charge SDK admission and filesystem change discovery when that adapter is used. The editor interaction remains a narrow inspect/compile proof, not a complete diagnostics loop.

The question is whether a shared authoritative input generation reduces repeated target validation at useful repository sizes. Success means lower complete-operation latency without stale readiness, excessive retained generations or weaker invalidation.

## Establish bounded tool lifetimes

Native and [JVM compiler](compiler/jvm/prospects.md) reuse justify longer sessions. The [longer traces](java/followthrough.md) now exercise a soft PSS gate, NMT diagnostics and concurrent chunk-cache pressure; they do not enforce a quota, establish JIT convergence or identify every resident allocation. Next test genuinely varied production targets with mapping-level attribution and a declared resource policy. Preserve whole Java targets until an incremental compiler provides a stronger grouping contract. Native user-profiled O3 needs unseen-target evidence and preparation amortization; its sustained advantage over O3/inferred profiles is currently small and noisy.

A managed service should earn its lifetime complexity through amortized complete workflows and bounded resource use. Short warm measurements and serialized cache limits are not sufficient memory guarantees.

## Make artifact access useful under real network and cache conditions

The [artifact work](artifacts/prospects.md) now includes synchronous demand consumption, verified chunk budgets and a 3,931-object lifecycle trace. Next demonstrate actual useful-work/transfer overlap and extend cache lifetimes beyond owned byte views. Include bandwidth limits, realistic latency and a competent native HTTP implementation before attributing a general win to binary framing.

Producer indexes and binary locks have already removed much repeated metadata work. Measure remaining shared lookup/cache work in both flat and ZIP controls. Keep name/version discovery, ecosystem resolution, metadata trust and content transfer as separate contracts.

The [storage-service model](storage/prospects.md) demonstrates latency gains and bandwidth losses from full memory admission. Test demand granularity, selective admission and longer reuse, then validate on an isolated actual storage setup. Warm page-cache hits need not encounter device throttling; a logical service delay is a separate contract.

## Prepare framework data only where the complete tool benefits

For [Groovy](java/prospects.md), the prepared runtime-image map improves isolated lookup without a complete-command gain. Require a profile showing meaningful complete-operation work before another table format or broad archive. Preserve fresh loaders, mutable bindings, uninstrumented controls and prior negative runs. For [Ruby](ruby/prospects.md), test whether unused pack/index data can stay outside eager Ruby objects while preserving require behavior and full verification.

A broader [Node/Python session](python/prospects.md) must beat competent cache baselines and justify preparation/rebinding costs. A broader [.NET workload](dotnet/prospects.md) must justify its modest composite-R2R gain and servicing cost. Preserve negative results when changing the workload.

## Take shared representations into real consumers

The catalogue and synthetic schema results justify a real diagnostics/dependency/test-result consumer that avoids equivalent object graphs. Compare competent existing APIs and parallel independent consumers, not only repeated sequential parsing. Protobuf's rejected descriptor case requires explicit/default/source metadata to remain part of the representation contract; semantic-looking data is not automatically an exact regeneration boundary.

The [testing prospects](testing/prospects.md) call for production suites and explicit fixture isolation. Existing JUnit discovery and prepared SQLite APIs already capture much of the demonstrated benefit. The next value lies in safe composition, ownership, invalidation and complete workflow costs.

## Keep product design separate

The Odin checkpoint probe is only a persistence boundary; the [source-control milestone](../components/source-control/milestone-1.md) still needs discovery/ignores, symlinks, stack/change records, safe restore and automatic recovery. The [editor](../components/editor/README.md), [dependency](../components/dependencies/README.md) and [artifact-host](../components/artifact-host/README.md) interfaces need their own scoped decisions. Experimental encodings and local process arrangements should not become public standards by accident.
