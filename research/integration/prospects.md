# Next concrete integration boundaries

The [four-project follow-up](generalization/README.md) tests frozen reuse and bounded frontend/backend scheduling. Start with diagnostic retention and cache admission under a real byte budget. re2c’s unchanged files still trigger compiler work when they emit warnings; curl’s broad edits displace earlier results. Preserve current diagnostic locations, namespace absence and full physical-output checks when improving either policy.

The [refinement](refinements/README.md) now measures early frontend-facts publication, retained immutable identities and bounded multi-version result reuse. Restricted numeric-macro changes can reuse unaffected targets. Keep the original shared path and Ninja + ccache with the same fast index as controls.

The queue now separates frontend readiness from backend completion, with private staging and explicit drains. It helps spdlog, uses serial fallbacks for re2c and slows curl’s edit trace. Profile its extra CPU and module/context ownership before changing the transfer model. Keep independently cached consumers and matched worker budgets as controls; mutable Clang/LLVM state is not assumed thread safe.

Separate object reuse from facts freshness earlier. Header comments and inline-function additions favour different cache layers. Test a generic gate before costly lowering, avoid publishing unchanged object bytes unnecessarily, and charge all required link work. Add natural upstream patches and a real editor/analyzer with varied queries: four source projects still share one fact-summary/prefix consumer.

Retained facts and lexical footprints increase memory. First attribute source, result-history, identifier and compiler allocations over a longer session. The current LRU history bounds counted payload/entries; its allocator/container costs and separate IR/lexical caches do not fit a proven RSS quota. Dependency-aware retention remains a separate experiment, with recency as its baseline.

Configuration projection intentionally handles only a restricted class of numeric definitions. Unknown options and metadata-sensitive modes retain exact contexts. Broaden effect capture only with explicit correctness rules and stock-output counterexamples. ABI, optimization, target, language and debug choices must stay part of the backend identity. Fixed SDK namespaces need their own immutable admission contract before arbitrary live SDK changes are supported.

The refined full scan still sends current command arrays and checks target observations. Register immutable command identities once and measure compact bindings or maintained frontiers before another binary format or SIMD kernel. Preserve namespace absence, shadowing, current diagnostics and failure-path behavior. The separate retained-scan and complete workflow clocks describe different operations.

For SIMD, native auto-vectorization and sparse representations remain essential controls. The current small graph fits one word; wider generated-mask wins do not imply faster complete builds. Use a genuinely larger captured relation and charge index construction/change discovery before selecting dispatch policies.

The created-header cache diagnostic still requires a real filesystem adapter: declared fixture hints and preprocessor-cache fallback are not general automatic Ninja invalidation. Production protocols, tool compatibility and durable service recovery remain open.
