# What should follow the adjacent workflow proofs

## Use native pipeline interfaces before another process bridge

The decoded-image Python bridge loses to existing ffmpeg controls. A next asset experiment needs a larger real workload and an existing library interface or retained process, with complete decode/transform/encode costs and memory lifetimes. A photographic/video or scene workload would be new evidence. Hardware initialization must be distinguished from verified device execution and end-to-end benefit.

## Expand native replacement only through declared state

The scalar ABI has no outstanding pointers, callbacks or concurrent invocations. Add explicit state migration, quiescence and initialization failure semantics before complex application updates. Preserve a competent batch process and charge changed-module compilation/linking. General dynamic-library constructors can have effects before ABI validation; current rollback checks do not contain them.

## Exercise a real multi-client provider

The workspace trace hosts four actors in one Python process with ordered updates. Compare parallel independent processes, immutable filesystem sharing and a real provider protocol under matched CPU/memory budgets. Integrate accurate dependency observations and bounded cache/lease retention. A shared dictionary is not a demonstrated RSS bound or complete filesystem adapter.

## Test feedback beyond a deliberately queued burst

Queued cancellation should next face actual rapid edits, several clients, varying task costs and background work. Record current useful response latency, waste and starvation. Already-running analysis must retain generation checks; durable acknowledged operations need separate completion semantics. Preserve current syntax-error and conflicting-update controls.

## Broaden prepared testing with an explicit reset contract

The actual stdlib documentation subset improves by retaining an existing API; batch execution is still best. A production suite with meaningful framework/database setup would test a different boundary. Include changed modules, mutable framework state and external effects, plus setup, teardown and memory. Reusing an interpreter is not automatically equivalent isolation.
