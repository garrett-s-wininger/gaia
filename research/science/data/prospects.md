# Next boundaries for sets and adaptive data

First test maintained reconciliation summaries with incremental Merkle updates and actual synchronization, charging construction/verification and fallback. A cold Python sketch is not a verdict on native performance, and metadata bytes alone do not establish useful acquisition time.

For delivery, calibrate one bounded controller against fixed finalists on genuinely changing real transports and larger objects. Add enforced byte admission cases and instrument CPU/transient memory separately. Current batches are small and the 4 MiB in-flight limit is not stressed; no OS memory-pressure result follows.

For locality, preserve BFS, static clustering and single-chunk/cost-size controls. Broaden to different applications and changing live sets, then include active mapped readers, incremental repacking and durable publication. Reinforcement and force embedding currently lose simpler controls. The shared chunk LRU differs from the parallel graph study's group-cache model, so their byte counts cannot be combined.

For environment construction, compare a real writable tool environment or offline image lifecycle with its existing cache/link mechanisms. The current read-only application contract already permits ordinary symlinks. SDK acquisition, writable isolation and actual lazy image transfer remain separate costs.

For representation laws, add a second independent reader and version negotiation before proposing a protocol. Preserve explicit/default/source metadata and opaque optional fields; a fast lossy projection is not an exact regeneration proof. Keep policy training and held-out evaluation separate, with enough workload diversity to justify adaptation beyond a fixed policy.
