# Interpreter-state reuse research

This independent Python research track reopens [PY-FMT-04](../../../research/python/follow-up.md). The question is whether initialized interpreter/dependency state can avoid work left after dependency-format improvements. The first experiment distinguishes resident CPython fork templates from actual serialized Node startup snapshots.

Read the [results](results/initial/REPORT.md) for measurements and limits. Neither mechanism is a portable dependency format or a selected Gaia architecture.

## Reproduce the Python comparison

Use the existing [pinned Django wheel acquisition](../dependency_bundles/fetch_django.py):

```sh
python3 -B experiments/python/dependency_bundles/fetch_django.py
python3 -B experiments/python/interpreter_snapshots/benchmark.py \
  --wheels experiments/python/dependency_bundles/_work/django-corpus/wheels \
  --trials 7 \
  --output experiments/python/interpreter_snapshots/_work/main
```

The provenance defaults to the checked-in Django acquisition manifest. Inputs are hash checked and extracted locally; dependencies, fixture and harness are precompiled before measurements. All variants use identical `python -I -S -B` behavior and the same precompiled runner. Preparation and template creation/shutdown are recorded separately. A template receives one request at a time; the full child lifecycle, including IPC, normal Python finalization and wait, is timed. Parent JSON decoding and independent semantic comparison occur afterward. Warm page cache is explicit.

The [generic runner](runner.py) loads a workload module exposing `prepare(stage, config)` and `run(request)`. The [Django adapter](django_workload.py) provides minimal/import-only/framework stages. Framework preinitialization is an explicit workload hook. Existing Django versions, resources, module origins, system checks, ORM results and first API/admin responses are validated. This fresh comparison is not directly comparable in absolute times with the older loader experiments.

The prototype accepts one single-threaded Linux template with no open file descriptors beyond stdio before each fork. It rejects unexpected live resources or OS threads. Corpus, runtime, import path, cwd and protected settings environment are fixed for a template session; changing them requires rebuilding the template. Other per-request env/argv fields are bound before workload execution, but arbitrary imported libraries may already have cached environment state. The experiment does not promise generic rebinding of imported state. The module-global Python random generator is reseeded; arbitrary RNG/native handles need explicit hooks.

Every request uses a fresh child. Failed child work cannot mutate the parent interpreter's Python heap, but external side effects still need their own isolation. Child execution returns through `main` and `sys.exit`; it does not use `os._exit`. The parent waits for finalizers before returning a reply.

## Correctness tests

```sh
python3 -B -m unittest discover \
  -s experiments/python/interpreter_snapshots -p 'test_*.py' -v
```

The tests exercise mutable globals, env/argv/cwd binding, nonrepeating random output, normal `atexit` execution, child-error recovery, resource/thread rejection, pinned environment/cwd mismatches, unknown request fields and request limits. No wheel download is needed for these tests.

## Serialized runtime sanity check

```sh
python3 -B experiments/python/interpreter_snapshots/node_benchmark.py \
  --node /usr/bin/node --trials 7 \
  --output experiments/python/interpreter_snapshots/_work/node
```

This small synthetic check actually builds a Node startup blob and restores it in fresh processes. It compares empty and 100,000-row metadata graphs, validates lookups plus runtime env/argv, and records blob creation time/size separately. It does not measure an industry Node tool or establish an ecosystem gain. Blob compatibility is tied to the measured runtime; storage-cold pages are not simulated.

Generated bytecode, wheel contents, runtime blobs and raw observations stay in ignored `_work`. Published reports and compact evidence are retained under `results`; raw results are ignored and registered in the repository evidence manifest.

## Real compiler dependency snapshot comparison

The [TypeScript comparison](results/typescript/REPORT.md) audits the synthetic experiment and measures actual TypeScript 5.9.3 initialization. Acquire the exact pinned archive and run:

```sh
python3 -B experiments/python/interpreter_snapshots/fetch_typescript.py
python3 -B experiments/python/interpreter_snapshots/node_dependency_benchmark.py \
  --node /usr/bin/node --trials 7 \
  --output experiments/python/interpreter_snapshots/_work/typescript-results
```

Use a new output directory for each run. [Acquisition](fetch_typescript.py) verifies the checked-in npm SHA-512/SHA-256 pins, archive paths are checked before extraction, and third-party source remains ignored. The upstream 9 MB single-file compiler is embedded byte-for-byte in its ordinary CommonJS wrapper. The comparison holds this exact generated bundle fixed across ordinary execution and default/no-code-cache snapshot restoration, with a separate stock `require` control. No AST/request result or transpilation is prepared before the snapshot.

Requests supply source text at runtime, alternating cwd and current env/argv. Every mode must produce identical AST counts, diagnostics, emitted JavaScript and source maps; both restored modes also run after the upstream source file is hidden. A retained build-only marker proves module initialization is not rerun during restoration. A runtime exit marker proves ordinary process exit completed. Generated code/blobs stay ignored; blob generation and snapshot memory are reported separately. The TypeScript adapter covers syntax/AST/transpilation, not arbitrary compiler-server/watch/native-resource behavior.

## Full TypeScript project CLI

The [project CLI comparison](results/typescript-project/REPORT.md) uses the real published `exponential-backoff` 3.1.3 sources, genuine TypeScript standard libraries and upstream `executeCommandLine` for config discovery, module loading, full checking and filesystem emission. Reproduce with:

```sh
python3 -B experiments/python/interpreter_snapshots/fetch_typescript.py
python3 -B experiments/python/interpreter_snapshots/fetch_backoff.py
python3 -B experiments/python/interpreter_snapshots/node_project_benchmark.py \
  --node /usr/bin/node --trials 7 \
  --output experiments/python/interpreter_snapshots/_work/project-run
```

Use a fresh output directory. The real project sources remain unchanged; Jest specs are excluded and a small consumer changes at runtime. The explicit tsconfig enables full ES2020/DOM declaration checking, strict mode, `noEmitOnError`, JS/declaration output and both map formats. Input edits and output cleanup are outside compiler clocks; all config/source/standard-library reads, type checking and output writes are inside. All outputs and diagnostics must match stock CLI, and emitted code is independently run afterward.

Five matched controls include ordinary `tsc.js` with its normal warmed Node compile cache, cache-disabled `_tsc.js`, compiler API require, identical compiler API bundle and default module-initialization snapshot. First cache-creating execution, cache bytes, snapshot creation and rebuild are separately recorded. No project/AST/diagnostics/result or standard-library parse is retained in the snapshot.

[The performance bridge](typescript_performance_bridge.js) leaves upstream compiler bytes unchanged while supplying its `perf_hooks` dependency through a forwarding object. During preparation that object contains no native performance handle. A deserialize callback binds the current runtime's real `perf_hooks`, avoiding the earlier serialization warning. [The runtime adapter](typescript_cli_workload.js) checks current timestamps, epochs, marks/durations, cwd/env/argv and normal exit; an actual extended-diagnostics correctness case also validates live compiler timing/counts. This explicit adapter covers the pinned nonwatch CLI contract, not arbitrary Node builtins, compiler versions or persistent project-service resources.

Correctness boundaries include a semantic type error with no emitted files, invalid tsconfig with stock exit/output behavior, changed target options, extended diagnostics, rejected compiler-version/environment contexts and rejected watch mode. Native resources/watch/incremental/build/profiling modes are outside this first experiment. All native/runtime artifacts remain ignored.
